# Vinx Ingestion API (Phase 2)

The Android client pushes perception events (notifications, screen OCR, voice,
clipboard, app sessions, etc.) into Vinx through a single authenticated
endpoint. Events are queued server-side, deduplicated, and processed in
60-second batches by the 6-agent AI pipeline.

## Base URL

```
https://lotrulidgneaeysgblok.supabase.co/functions/v1
```

## Authentication

Use a long-lived **Device Key** generated by the user in **Settings → Device Keys**.
Keys are returned exactly once (prefix `mm_…`) and stored only as a SHA-256
hash on the server. Send the key on every request:

```
Authorization: Bearer mm_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
Content-Type: application/json
```

Revoke a key from Settings; the server rejects it immediately.

## POST /context-ingest

Push one or many events. Returns `202 Accepted` immediately — processing is
asynchronous.

### Single event

```json
{
  "source_app": "YouTube",
  "app_package": "com.google.android.youtube",
  "platform": "android",
  "capture_type": "screen_ocr",
  "raw_content": "Veritasium — The Insane Engineering of the A-10 Warthog",
  "timestamp": "2026-06-04T14:32:11Z",
  "metadata": {
    "screen_id": "watch",
    "confidence": 0.93
  }
}
```

### Batch (preferred for background services)

```json
{
  "batch": [
    { "source_app": "WhatsApp", "app_package": "com.whatsapp",
      "platform": "android", "capture_type": "notification",
      "raw_content": "Mum: don't forget the dentist tomorrow at 3",
      "timestamp": "2026-06-04T14:31:00Z", "metadata": { "channel": "msg" } },
    { "source_app": "Chrome", "app_package": "com.android.chrome",
      "platform": "android", "capture_type": "accessibility",
      "raw_content": "stripe pricing page — 0.5% on standard volume",
      "timestamp": "2026-06-04T14:31:42Z" }
  ]
}
```

### Field contract

| Field | Required | Notes |
|-------|----------|-------|
| `raw_content` | yes | Plain text. Max 50,000 chars. |
| `capture_type` | recommended | `screen_ocr`, `notification`, `accessibility`, `clipboard`, `voice`, `manual`, … |
| `source_app` | recommended | Human-readable app name. |
| `app_package` | recommended | Android package id — enables filtered retrieval. |
| `platform` | optional | Defaults to `"android"`. |
| `timestamp` | optional | ISO-8601, when the event was observed on device. |
| `metadata` | optional | Free-form JSON the AI pipeline preserves. |

### Response

```json
{ "accepted": 12, "queued": 9, "deduped": 3 }
```

## Deduplication

Identical normalized `raw_content` from the same user within a 10-minute
window is dropped at the edge. Safe for the Android client to retry, and
safe for noisy sources (e.g. the same notification being re-emitted).

## Batching pipeline

```
Android client ─POST─▶ /context-ingest ─▶ ingestion_queue (Postgres)
                                                  │
                              cron every 60s ─────▶ process-ingestion-queue
                                                  │
                                       raw_memories + 6-agent pipeline
                                                  │
                              structured_events · pending_intents · entities
```

## Retrieval metadata

Memories and vectors are tagged with `platform`, `app_package`, and
`capture_type`. The query layer can now filter, e.g.:

- "things I saw on Twitter last Tuesday" → `app_package = com.twitter.android`
- "voice notes about Helena" → `capture_type = voice`
- "screen captures from YouTube" → `app_package = com.google.android.youtube AND capture_type = screen_ocr`

## Rate / cost notes for the Android client

- Prefer `batch` over per-event calls (one HTTP round-trip per ~60s window).
- Skip OCR text that hasn't changed between frames before sending.
- Don't push raw audio — transcribe on-device via `voice-to-text` first.
- The server already dedups, but cheap client-side dedup saves bandwidth.

## Errors

| Status | Meaning |
|--------|---------|
| 401 | Missing or revoked device token. |
| 400 | No valid events in payload. |
| 405 | Use POST. |
| 500 | Server error — retry with backoff. |
